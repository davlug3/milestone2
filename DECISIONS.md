# Decisions

- Units: meters.
- Coordinate convention (world): X = book width, Y = world up (book thickness), Z = book height (head-to-tail). Spine runs along Z at x = -width/2. Open book lies on the XZ plane; gravity is -Y. This supersedes PLAN.md section 3.1, which described an upright book and conflicted with gravity -Y for a book on a surface.
- Renderer: Three.js WebGLRenderer / WebGL 2.
- Physics: custom PBD/XPBD for the active page.
- Simulation timestep: fixed 1/120 second initially.
- Active dynamic pages: one initially.
- Final shot duration: 25 seconds.
- Final animation: deterministic and cacheable.
- Build system: Vite (no existing build system in repo at start).
- Language: TypeScript (strict).
- Folder layout: `src/app`, `src/config`, `src/book`, `src/paper`, `src/physics`, `src/animation`, `src/rendering`, `src/testing`, `src/assets`.
- Bending: two-step neighbor distance constraints (soft, stiffness ~0.35), configurable via `bendStiffness`. Dihedral bending deferred.
- Paper thickness: thin-shell render (front/back offset along mid-surface normal + perimeter edge), default 0.25 mm visual.
- Sim tests run headless via `npm run test:sim` (esbuild bundle + node).
- Sheet topology supports two rest planes: 'xy' (vertical, drop tests) and 'xz' (flat, page turns).
- Page turn: kinematic corner pin driven by `PageTurnController` (lift/peel/arch/cross/fall/settle via eased target); never rigid rotation. Ground collision (y clamp) for landing.
- Test scenes selectable via `?test=paper-drop|paper-edge|page-turn|book`; `?t=<seconds>` freezes a page-turn frame for deterministic screenshots.
- Page turn v2 (realism fix): drive the WHOLE fore-edge (not a single corner) along a semicircular arc of radius = page width about the gutter. Radius = width keeps the sheet at natural length so it never buckles into a gutter crease. High bending stiffness (1.0) + 12 solver iterations distribute curvature smoothly. After the sweep the fore-edge is held at its final rest position so the page settles on the destination (left) stack instead of crumpling. Objective smoothness verified via `npm run test:page` (worst dihedral 15.6 deg, stretch <=1.08x).
- Page turn v3 (curl + collision): liftScale 0.6 (real curl, not a rigid flat flip) + long-range bending constraints (3- and 4-cell spans) so curvature spreads across the sheet instead of buckling into one crease (dihedral 57 deg -> 29 deg at ~8 cm curl). Lowered the spine strip to page-block-top height so pages no longer intersect the spine mesh (was the "folds through binding" bug). Added shadow normalBias to kill shadow acne (dark triangles). Ground clamp at block-top height + per-page rising ground = pages rest on the book and stack without penetrating. Verified via `npm run test:page`: curl 7.9 cm, dihedral 29 deg, penetration 0, stretch <=1.07x, crosses fully and settles flat.
- Page turn v4 (2D curl + closed start + heightfield): per-row phase `lead` (0.04) and `liftVar` (0.06) make the head/tail of the page lead/curl differently -> a 2D surface bend, not a uniform cylinder about one axis. Separate `restY` (spine/gutter height) and `landY` (destination fore-edge height) so the page starts on the tall right stack and descends onto the low left stack. Solver gained a `groundHeight(x,z)` heightfield callback: tall right stack (blockTop) vs low left (landY) so the page cannot pass through the book or other pages. Reworked the demo to start genuinely CLOSED: removed the left page block, pages rest under the closed front cover on the right; left side is empty until the cover opens and pages land there. Verified: t=0 shows only ~1.4k paper samples (closed) vs ~34k when open; `npm run test:page` stretch 1.11x, dihedral 35 deg, penetration 0, curl 7.4 cm, crosses and settles. Note: pushing the 2D effect harder over-stretches the (near-inextensible) sheet, so lead/liftVar are kept small; a stronger 2D curl would need a prescribed (kinematic) surface.- Page-turn v5 (persistent 15-sheet book + real page-to-page collision): the book is now ~15 visible sheets (8 turning + 7 static boxes) present from t=0, so pages persist before and after the shot instead of appearing during it. Collision uses a shared `Heightfield` (`src/physics/Heightfield.ts`, ~110x110 cells over both sides): base = right block top vs opened-cover top, and every settled sheet is baked in (outer region only, leaving a 4 cm gutter strip free for a natural fan). The active sheet samples `heightAt(x,z)`, so it rests on the real shape of the pages below. Each page lands at `landBase + k*0.0008`, which exceeds the 0.6 mm bake clearance, so pages stack without interpenetration. The right side of each page uses `max(sheetBelowRestY, heightfield)` so it cannot sag into the stack it sits on. Verified with `npm run test:twopage` (8 pages, 4389 checks, 0 particles >0.5 mm below the pages beneath).
- Shadow-acne root cause fixed (`src/paper/ThickSheetGeometry.ts`): the grid cross product was `e1 x e2`, which points -Y for a sheet built in the XZ plane with rows along +Z. That made the mid-surface normals (and therefore the shadow `normalBias` offset) point into the page, producing heavy moire self-shadowing on every deformable sheet. Switched to `e2 x e1` (+Y) so the rendered front surface is also the front-facing one. With correct normals, `normalBias` 0.002 + `bias` -0.0001 at 2048 shadow map is acne-free.
- Paper grain texture now uses mipmapped trilinear filtering (was nearest-filtered DataTexture -> moire under minification). Kept even though the main moire turned out to be shadows.
- Page stiffness v6: pages were a little too floppy. `SheetTopology` now accepts explicit `bendSpans` (long-range bending link lengths in grid cells) via `createSheetTopology`/`PaperSimulation`. Longer spans resist large-scale curvature, i.e. stiffen the sheet without over-relaxing the 2-cell constraints (stiffness is already 1.0). Demo/test scenes use `bendSpans: [3, 4, 5, 6]` (was the implicit `[3, 4]`). Measured with `npm run test:page`: worst fold angle 33.7 deg -> 27.3 deg, stretch 1.17x -> 1.21x (still within budget), penetration 0. Sweeping further (adding span 7-8, or raising long-range stiffness to 0.75/1.0) raised the fold angle again (over-constraint jitter) and increased stretching, so [3,4,5,6] at the default 0.5x long-range stiffness is the chosen setting.
- Page turn v7 (hinged cover + page/cover collision + spine settle): the front cover is now a rigid board parented to a pivot group at the spine (x=0) with the board offset +W/2, so it opens by rotation alone. `src/book/coverRig.ts` owns the kinematics: `coverPose(u, closedCenterY, openCenterY)` holds the hinge at the closed cover plane until the board passes vertical (`HINGE_DROP_START = 0.55`), then eases it down to `CT/2` with `smootherstep`; the swing itself is `PI * smootherstep(u)` over 2.2 s (0.6-2.8 s). The old centre-lerp + slerp + `sin(pi*p)*0.09` hop made the board detach from the spine, float, and sweep its trailing corner through the page block/table. Collision: the heightfield's left base and the page `landBase` now come from `openCoverSurface()` (inner lining top = open center + `CT*(0.5+0.1)` = 2.75 mm) plus half the page shell (0.125 mm) and 0.05 mm clearance = 2.925 mm, replacing the flat `CT` floor. `PageTurnController` gained `spineIndices`, `landSpineY` and `landSpineStart` (default 0.7): the gutter edge stays at the old stack height through the crossing (no fold over the block edge) and then settles to the destination stack, so a landed page lies flat in the gutter. The dark spine strip is now a low plinth at the open-cover top height (2.75 mm) instead of a 14.5 mm wall: a full-height strip was driven through by every descending page spine edge (black jagged fan) and towered over the landed pages. New headless `npm run test:cover` asserts cover endpoints/monotonic swing, no board/table or board/block interpenetration, open-cover surface height, and a page landing on the cover with spine + fore-edge both at landY and <1.5 mm spread. Verified: cover lowest Y = 0.00 mm, 0 board samples inside the block, page below-cover 0.05 mm clearance (above), spread 0.20 mm.
- Page turn v8 (curved gutter + per-page binding): the gutter is now a curve in the X-Y cross-section, not a straight hinge line. `src/book/gutterRig.ts` defines `gutterSurfaceY(x, u)`, `gutterParticleFloorY(x, u)` and `gutterBinding(s)` between the covers' inner lining edges (x = ±width*0.015 = ±3.6 mm); the surface dips from the lining top (2.75 mm) to the board top (2.5 mm) and the dip is scaled by the cover-opening progress `u`, so the hollow forms as the cover opens. Each sheet k binds at `s_k = (k+0.5)/8`, giving a unique world (x, y) point (x from -3.15 mm to +3.15 mm, y 2.68-2.88 mm). The demo passes `spineTargetX` and `landSpineY = binding.y` to `PageTurnController`; the gutter edge now moves in X and Y (not just Y) and the fore-edge still lands at the stack height, so the sheet curves up from its gutter point to the stack instead of being flat to a sharp x = 0 crease. The gutter plinth is a box whose top vertices follow `gutterSurfaceY` (beige `coverInner`, not the dark spine material, so the hollow reads as a surface). The right page block is set back to x = 5 mm with a 2.5 mm rounded inner-top edge (an extruded Shape) and the static sheets start at x = 7.5 mm, so the block no longer forms a vertical wall in the gutter and the sheets have room to curve. The heightfield base and every page's `groundHeight` now use the gutter floor for |worldX| <= 3.6 mm, `blockTop` for worldX >= 5 mm, and the cover floor elsewhere; the `belowRestY` clamp only applies over the right block (x >= 5 mm). `npm run test:cover` now asserts the gutter endpoints equal the lining top, the middle dips to the board top, binding x is strictly increasing, the page's spine edge lands exactly on its binding point, the fore-edge lands at `landY`, the spine edge is below `landY` (curved gutter), and no particle goes below the book surface. Verified: gutter edge 2.75 mm, middle 2.5 mm, page spine (0.000, 2.675) mm = binding, fore-edge 3.125 mm, spread 0.45 mm, below-surface 0.05 mm clearance; `test:twopage` 8 pages, 4488 checks, 0 penetration; `test:page` stretch 1.15x, dihedral 29.8 deg, penetration 0. Note: the open book still shows a dark band of table/background through the V between the low front cover and the taller right block; that is the table beyond the far edge, not a hole or a shadow (confirmed by hiding objects and disabling shadows). It can be reduced later by camera framing or a backdrop.
- Blender project (Option B): added a native Blender 5.3 reconstruction in `blender/`. `page_model.py` is a pure-Python analytic page model (cubic-Bezier curl with a tighter fore-edge bend, per-row lead/lift, a gutter binding point per sheet, and a flat landed stack with a curved gutter). `build_book.py` builds the covers, beveled page block with a rounded inner-top edge, curved gutter plinth (shape-keyed flat/dipped), 7 static sheets, 8 shape-keyed turning sheets, studio, camera and render settings, then saves `blender/book.blend`. `check_model.py` validates the page math without Blender (rest shape, gutter endpoints, landed fore-edge, flat stack, finite/above-table, centerline length, block clearance). Previews are rendered with Cycles because EEVEE Next shows a per-quad shading grid on the large flat page surfaces. The page turn is an approximation of the WebGL XPBD result, not a bake. Timeline: 30 fps, frames 1-919; cover 0.6-2.8 s; turns from 3.7 s; total 30.6 s. Run `blender -b -P blender/build_book.py -- --out blender/book.blend --preview`.
- Book thickness: increased the page-block thickness `PBT` from 12 mm to 22 mm in both the Three.js demo (`src/demo/bookDemoScene.ts`, headless test scripts) and the Blender model (`blender/page_model.py`). Closed book thickness is now ~27 mm (2 x 2.5 mm covers + 22 mm block). The taller block raises `blockTop`, `restBase`, the page rest heights, and the closed-cover hinge automatically; the cover opening, page turns, camera framing, and collision floors all adapt from those constants. Three.js tests pass (cover, 8-page stacking, page metrics stretch 1.15x / dihedral 29.7 deg / penetration 0); Blender `check_model.py` passes; Cycles previews inspected.
- Milestone 6 (animated spine + endpapers): the spine is now a curved case strip, not a static bar. `src/book/spineRig.ts` (pure math) defines a quadratic Bezier cross-section from the back board's top edge (0, CT) to the front board's outer hinge corner (hinge-line point rotated by the cover angle, offset CT/2 along the board's outer normal). `createSpineRig` in `src/book/spine.ts` sweeps it along Z with a 0.8 mm shell (front/back layers, head/tail/edge caps). The visible bulge is CT*1.6 = 4 mm when closed and eases to zero over u = 0.70-0.88. Flattening before u ~= 0.90 is required: the chord shrinks to zero and flips direction as the hinge drops past the back board's top edge, and a still-bulged strip folds into the back board there (caught by `npm run test:spine` at u = 0.897). At u = 1 the strip is a flush 2.5 mm ribbon at x = 0 inside the gutter footprint, hidden by the plinth and the open cover. The static Milestone 1 book uses the same rig at (u = 0, angle = 0, originX = -width/2). `npm run test:spine` samples 401 poses: attachments coincide with the hinge corners, the section stays on the outer side of its chord, never dips below the table, never enters the back board / page block / raised front cover, closed bulge is 4 mm with the chord across the block (29.6 mm), mid-open min x is -4.6 mm (outside the raised board), open pose is inside the gutter footprint and below the lining with zero bulge, the bulge is monotonic in u, and the 350-vertex shell is finite with a double-sided material.
- Endpapers and the finished joint: `materials.endpaper` (0xcdbfa4) and `endpaperHinge` (0xb3a488) replace the old `coverInner` singleton. The pastedown is the cover lining plus a 6 mm darker crease strip along the spine edge, so the opened cover shows a fold instead of a bare panel. The front and back flyleaves are the first and last *turning* sheets, tinted endpaper stock (0xd8ccb4) but otherwise the same simulated sheets - no extra physics. The gutter plinth's top is endpaper stock and its sides are spine cloth; its top face swaps to spine cloth while u < 0.5, because the beige joint floor otherwise peeks out beside the closed/early-opening spine as a bright rim (a residual 1 px rim remains only in extreme table-level close-ups, outside the shot framing). The plinth's material groups are BoxGeometry's (+x, -x, +y, -y, +z, -z), i.e. index 2 is the animated top.
- Stacking z-fight fix (found by the tinted flyleaf): the demo's right-side collision clamp used `belowRestY`, which is the sheet-below's *mid-surface*. A turning sheet could therefore lie exactly flush with the sheet underneath and z-fight (large cream/white patches). The clamp is now `belowRestY + 0.00025` (one shell clearance). Rest spacing is 0.3 mm, so resting sheets still sit on their own heights.
- Visual validation tooling: `scripts/preview-spine.mjs` captures eight spine/endpaper close-ups via the dev-only `__demo.camera` hook; Playwright Chromium and its apt dependencies were installed in this devcontainer, and headless WebGL 2 runs on SwiftShader (software). Software-rendered frame rates are not used as performance evidence.
- GPU usage: every scene's `WebGLRenderer` now passes `powerPreference: "high-performance"`, so a client/host with a discrete GPU is used when the browser exposes one. This is a hint only; browsers without a usable GPU fall back to whatever they have (software SwiftShader, integrated GPU). The demo exposes `__demo.gpu()` (actual `UNMASKED_RENDERER_WEBGL`/vendor) so validation can state the real backend instead of assuming it.
- Preview tooling uses the host GPU when available: `scripts/lib/browser.mjs` detects a DRM render node (`/dev/dri/renderD*` on Linux; macOS/Windows are assumed to have a GPU; `PREVIEW_GPU=0/1` forces the choice; `PREVIEW_GPU_ARGS` adds flags) and, when present, launches the full Chromium build in new headless mode with `--enable-gpu --ignore-gpu-blocklist`; otherwise it uses the headless shell. The reported backend comes from `WEBGL_debug_renderer_info`, so "gpu-preferred" still reports "backend: software" on hosts with no usable render node. In this devcontainer only `card0` exists and every variant reports SwiftShader, so the hardware path is implemented but was not exercisable here.
- Preview server lifecycle: `scripts/lib/server.mjs` spawns Vite directly (`node_modules/vite/bin/vite.js`) with `--strictPort` and SIGKILLs it afterwards. The old `npx` spawn left orphan servers bound to the preview port; later runs then served a stale build while fetching a hashed asset that no longer existed (spurious 404). `index.html` also carries an inline SVG favicon, which removes the only remaining automatic 404 in headless runs.
- Page vs case-binding clearance (post-merge fix): the anatomy pass put a 45-degree shoulder and an 8 mm round into the text block, so its solid started near x = 0 at y ~= 2.5-10.5 mm while pages bind at ~2.7 mm and ramp to the stack (~24.5 mm) within one 10 mm grid cell. The paper cut through that wedge. The demo's right block is now cut back to `BLOCK_INNER_X` (5 mm) below the top with a rounded inner-top edge (the v8 shape); the rounded/backed look lives in the cover-spine ribbon, outside the page zone. The heightfield was also limited to `blockWidth` (W - 4 mm), which pushed the last 4 mm of every sheet down to the cover floor and through the block; `blockTop` now covers every x >= BLOCK_INNER_X. Pages sit inside the hollow (x >= 0) and rest above the spine ribbon's top edge (floor 2.675 mm vs ribbon top 2.5 mm at u = 1), so no particle crosses it. New `npm run test:clearance` simulates sheets 0, 3 and 7 with the demo's exact floors/heightfield and asserts: no particle below the per-x floor (block top, gutter particle floor, open-cover floor), no particle inside the text-block solid, no NaN, no particle below the table - 0 penetrations. `npm run test:cover`, `test:page`, `test:twopage`, `test:spine`, `test:sim` still pass.
- Case spine panel width (open-book length): the spine panel is a flat strip of width `T` (closed book thickness = 2 boards + 22 mm block = 27 mm) between the boards. Closed it wraps around the block and does not add to the board width; open it lies flat between the boards, so the open book is `2L + T` long. `coverPose` now carries `hingeX`, moving the front hinge from 0 (closed) to `-SPINE_PANEL_W` on the same ease as the hinge-Y drop (`dropStart` 0.55); the demo sets `coverPivot.position.x = pose.hingeX`. `openCoverSurface` takes a `hingeTravel` and places the open board at `[-T-L, -T]` (open span = 507 mm for L = 240 mm, T = 27 mm); `cover-check` asserts the open span equals `2L + T` and the open hinge x equals `-T`. The spine ribbon's endpoint follows the moving hinge, so the open ribbon is a `T`-wide panel instead of the previous ~2.5 mm sliver. Landed pages follow the board: `PageTurnController` gained `landOffsetX` (demo: `-T`) which shifts the fore-edge arc centre and the spine target during the settle, so pages land at `[-T-L, -T]` with their fore-edges flush with the cover. The landing spine height is raised to `max(binding.y, coverFloor)` (2.925 mm) so the page's inner edge sits on the cover rather than 0.25 mm into it. Closed state is unchanged (board `[0, L]` plus the 12 mm spine bulge, i.e. ~252 mm overall). `cover-check`, `clearance-check` and `multipage-check` mirror the shift; all pass, and the visual pass confirms the open joint shows the `T`-wide spine panel.
- Inner hollow lining (binding line): the `2L + T` open book left a T-wide see-through joint between the landed pages' inner edge (x = -T) and the right block (x = BLOCK_INNER_X). Added a `hollow-lining` mesh whose top follows the joint profile - lining top (2.75 mm) across the joint, dipping through `gutterSurfaceY` to the board top (2.5 mm) at the centre - extruded 0.99H deep from `x = -T - 0.5 mm` to `BLOCK_INNER_X + 0.5 mm` (ends tucked inside the front cover and the block). Material is endpaper when open and spine cloth while closed (u < 0.5), so the closed spine stays dark. This is the common bound line for both page stacks: the pages' inner edges terminate on it and the table is no longer visible through the joint. The collision floors already match it (cover/joint particle floor 2.925 mm = 2.75 + shell half + gap; gutter floor from `gutterParticleFloorY`), so no physics change was needed; `cover-check`, `clearance-check` and `twopage` still pass, and close-ups at t=30 and mid-turn show the joint filled. The lining must not stay full width while closed: closed it is scaled toward the block's inner face (0.7 mm sliver tucked under the block/spine) and expands to the full T-wide joint with the cover-opening ease. Otherwise it lies under the closed case and its edge peeks out beside the spine at table level. Visual check: hiding `hollow-lining` at t=0 must not change the closed silhouette.
- Solid case C-section spine (demo): the visible spine is no longer a zero-thickness ribbon or a separate slab. `src/book/spineRig.ts` samples a C cross-section from the back board's hinge face to the front board's hinge face: a centerline whose sine bulge (closed, up to ~12 mm outward) eases to zero as the spine panel flattens; outer and inner rings are offset `+/-CT/2` along the section normal, so the shell is board-thick and its end caps land flush on both hinge faces. The ribbon is swept along Z with end caps (head/tail) plus the two board-face caps; the front cap uses the board's OUTER face (local +Y is outer: up when closed, down when open), which was the initial orientation bug. The outer ring continues 3 mm past each hinge (`SPINE_TURN_IN`) on the boards' outer faces, 0.1 mm proud, so the cloth wraps the hinge and hides the bright bevel line that appeared where the cover's spine edge met the dark shell. `spineCoverGeometry` has fixed topology so `updateSpineCoverGeometry` can rewrite the position buffer each frame. `npm run test:cover` now also asserts the shell is finite, stays above the table (turn-in tolerance 0.2 mm), does not enter the back board/block/raised front board, spans `x = [-T, 0]` and `y = [0, CT]` when open, and bulges outward when closed.
- Headbands in the open joint: the two red cord bands were sitting at x = 2.5 mm with a horizontal orientation, i.e. inside the right block and invisible. They now run vertically on the block's cut-back inner face (`x = BLOCK_INNER_X - 0.8 mm`, half a block thickness tall, full `PBT` depth) at the head and tail, so they are hidden by the case when closed and read as small red dots at the spine ends in the open joint.
- Case-spine variants kept separate: the tested quadratic-Bezier case strip (`src/book/caseSpineRig.ts` + `src/book/spine.ts`, `npm run test:spine`) remains for the static `?test=book` scene. The cinematic demo uses the solid C-section above; both are documented so a future merge does not replace one with the other accidentally.
- Bound spine (pages attached to a spine plane, not loose sheets): the gutter is now a horizontal cloth plane between the two cover hinges (world `x = 0` and `x = -SPINE_PANEL_W`), not a trough. `src/book/spineBinding.ts` defines the plane height (`spineClothTopY = CT * 1.1`, particle `spinePlaneY = cloth + shell/2 + gap`), the per-sheet fan step (`SPINE_FAN_STEP = 0.28 mm`, slightly over the 0.25 mm shell so sheets do not interpenetrate at the spine), and the ramp (`BIND_RAMP = 50 mm`). Every sheet's inner edge starts on the plane at its own fan height (`spineFanY`) and ramps up to its stack height (`rightSheetY` on the right, `leftSheetY` on the left), so the text block fans out of one continuous bound line. The text block is now a wedge whose top follows `blockRampY` (cloth height at the spine, flat block top at `BIND_RAMP`), so a turning page collides with a ramp instead of a vertical wall. A thin `spine-mull` cloth layer sits on the wedge and the `hollow-lining` is flat at the cloth height across the joint. `PageTurnController` gained `spineRestY` (default `restY`): the pinned spine edge now stays at its binding height through the whole turn (it no longer floats at the old stack height and then slides across the gutter), and settles at the front hinge on the left. The demo, `page-sim-metrics`, `cover-check`, `clearance-check` and `multipage-check` all use the new binding and the ramp-aware `groundHeight` (the sheet below is a ramp, not a flat height). `npm run test:page` worst stretch 1.18x, dihedral 35.9 deg, penetration 0; `cover-check`, `twopage` (5082 checks, 0 penetration) and `clearance-check` pass. Visual: t=0 still reads as a closed dark case; the t=30 front view shows a continuous mid-tone bound band between the two page stacks instead of a dark gap; the mid-turn page stays attached at the spine.
- Spine plane follows the front cover: `spinePlaneEdges(u, ...)` in `src/book/spineBinding.ts` returns the back edge (fixed on the back cover's inner lining, `x = 0`, `y = CT * 1.1`) and the front edge (the FRONT COVER's inner lining point at its moving hinge: `hingeX + CT * 0.6 * sin(angle)`, `hingeY - CT * 0.6 * cos(angle)`). The `hollow-lining` is now a unit box re-transformed every frame in `updateCover`, so its page-facing face is the plane: vertical when the cover is closed, following the cover through the swing, and flat at 2.75 mm when open. `cover-check` asserts the front edge equals the cover's lining point at `u = 0, 0.25, 0.5, 0.75, 1`. This fixes the earlier static/scaled strip, whose left edge drifted away from the front cover (at `u = 0.5` it was at `x = -13.6 mm` while the front hinge was at `x = 0`).
